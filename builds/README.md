# Kastel Builds

Builds turn selected Field Manual concepts into reproducible practical projects.

The aim is not to build everything in the fictional world.

A good Build should:

- solve one clear problem;
- use accessible components where possible;
- document cost and difficulty honestly;
- have a manual fallback;
- state legal/safety boundaries;
- use open formats;
- identify what was actually tested.

## Initial candidate builds

### BUILD-001 — Off-grid environmental node
Microcontroller + environmental sensors + LoRa + small solar supply.

### BUILD-002 — Private AI box
Local model runtime + private web interface + document search.

### BUILD-003 — Offline knowledge server
Small computer + SSD + Kiwix + local network access.

### BUILD-004 — Property water-level monitor
Tank or water-level sensor + local telemetry + alert.

### BUILD-005 — Local photo cloud
Self-hosted photo management + redundant storage.

### BUILD-006 — Household resilience dashboard
A simple local dashboard combining power, network, water and environmental state.

## What a Build may contain

- parts list;
- wiring diagrams;
- source code;
- configuration;
- CAD/STL files;
- photographs;
- test results;
- troubleshooting;
- change log.

Builds involving mains electricity, structural engineering, radio licensing, fire systems or other regulated/high-consequence domains must clearly identify where qualified help is required.
