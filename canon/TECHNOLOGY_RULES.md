# Technology Rules

## Principle

Kastel technology should feel advanced because systems are intelligently combined, not because every object is magical.

## Status system

Every significant technology receives one status:

- REAL NOW
- EXPERIMENTAL
- PROJECTED
- FICTIONAL

## Extrapolation rule

A PROJECTED technology should have named present-day ancestors.

Example:

```text
Kastel Field Node Mk IV — PROJECTED

2026 ancestors:
ESP32-class microcontrollers
LoRa / Meshtastic
solar charging
environmental sensors
local edge inference
Home Assistant / MQTT-style integration
```

## Human authority

AI may provide:

- perception;
- anomaly detection;
- search;
- summarisation;
- prediction;
- planning support.

High-consequence decisions should retain explicit human authority unless the story is deliberately exploring the consequences of losing it.

## Graceful degradation

Important node systems should have degraded modes.

Examples:

```text
fibre → 5G → satellite → local-only network
cloud AI → local AI → offline documentation
automatic irrigation → manual valves
digital access → mechanical override
server cluster → portable recovery machine
```

## Constraints make stories better

Technology should have:

- power requirements;
- maintenance;
- failure modes;
- cost;
- radio range;
- bandwidth;
- weather limits;
- human workload;
- legal constraints.

The project should prefer plausible imperfection over frictionless magic.
